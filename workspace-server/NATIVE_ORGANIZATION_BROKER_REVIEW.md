# Organization-native SSO preflight — diagnostic only (DORMANT)

This private source candidate is NOT imported or mounted by the active Workspace broker, account service or native apps. **No positive native preflight, even after a verified LIVE central per-app seat and signed ownership verification, is permitted to create a broker grant or app login.**

The private `inspectAccessCandidate(parent,appId)` diagnostic checks a canonical live parent; server-selected organization and monotonically increasing session-selection revision; active central user, current role and effective `workspace.view` permission; verified Stripe LIVE paid app capacity; exact org-scoped native identity link and its monotonic audit epoch; and a server-provided native ownership inspector. It rereads these authorities after awaiting the inspector and compares the revocation generations, role, paid period, parent and native tuple. It does not infer identity by email or accept legacy global grants. DataDuck remains excluded.

A positive diagnostic returns `candidateReady:true`, a private native identity tuple and a deterministic SHA-256 `bindingRevision` for **analysis only**, alongside `accessGranted:false`, `licensesGranted:false`, `loginEnabled:false` and `nativeEnforcementRequired:true`. It is not a token, certificate, native access approval or authorization code. The broker-facing `getAccess(parent,appId)` **always returns `null`**, without even executing the inspector. A diagnostic cannot be copied into a broker proof by this module.

A future grant-capable native SSO implementation must be a **separate, independently reviewed authorization protocol**, requiring real native server login/MFA policy, signed audience/parent-bound authorization with replay protection, LIVE per-app paid seats and current native scientific-resource ACLs. Do not turn a successful ownership inspection into an implicit SSO grant. Native services must enforce resource permissions independently for every protected read/mutation.

Focused tests now include **16** synthetic checks: current preflight and binding stability, cross-tenant denial, per-app and DataDuck exclusion, session-org/native-link/role and paid-period ABA, bad signed/central policies, and three explicit tests proving a positive preflight can never mint a broker grant. These are stubbed private stores, not genuine signed-native DB/HTTPS or Stripe. The tests need full exact-head Node 22/24 and browser execution when authorized CI/local source capacity exists; the prior 13 cases were reported as locally passing by the independent QA for PR #218. The additional tests have not been executed as an exact-head checkout.

**DRAFT ONLY:** no production, real customer payment, live login, native app changes or merges. The full eight-service staging, six-private signer source audit, native MFA/ACL, DataDuck backend acceptance and operator go/no-go remain mandatory.
